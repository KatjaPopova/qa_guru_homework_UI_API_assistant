# Дипломный проект по автоматизации тестирования Travel Assistant

Дипломный проект по автоматизации тестирования чат-ассистента «Кэп» на сайте tutu.ru, включающий UI- и API-проверки.

Проект реализован на Python и объединяет два уровня тестирования:

- **UI-тесты** — проверяют пользовательские сценарии работы чат-виджета в браузере;
- **API-тесты** — проверяют потоковый ответ ассистента, структуру событий и логику обработки запросов.

## Цель проекта

Цель проекта — автоматизировать проверку ключевых сценариев работы чат-ассистента и подготовить стабильный набор тестов, пригодный для локального и удалённого запуска.

Дополнительная задача проекта — показать комбинированный подход к тестированию одного продукта:

- через **UI** проверяется пользовательское поведение и работа интерфейса;
- через **API** проверяется логика ассистента, контекст диалога и структура потокового ответа.

---

## Что тестируется

### UI-сценарии

UI-тесты проверяют чат-виджет, встроенный в страницу tutu.ru и открывающийся внутри `iframe`.

Покрываются сценарии:

- открытие чата;
- отображение заголовка и приветствия;
- наличие поля ввода;
- наличие кнопки голосового ввода;
- наличие кнопки закрытия;
- наличие кнопки прикрепления файла;
- отображение быстрых подсказок;
- отправка текстового сообщения;
- запуск голосовой записи;
- загрузка файла;
- получение ответа на быстрые подсказки;
- негативные сценарии:
  - пустое сообщение не должно отправляться;
  - неподдерживаемый формат файла должен быть отклонён.

### API-сценарии

API-тесты проверяют поведение чат-ассистента на уровне backend-интеграции и потокового ответа.

Покрываются сценарии:

- корректность streaming / NDJSON-ответа;
- наличие `x-chat-hash` в ответе;
- сохранение контекста диалога между сообщениями;
- уточняющие вопросы при неполных travel-запросах;
- наличие suggestions в `serviceData`;
- отсутствие лишних support / purchase token в обычных travel-запросах;
- базовая проверка ответа на русском языке.

## Тестовая стратегия

Для проверки чат-ассистента используется комбинированный подход.

### Почему используются UI-тесты
UI-тесты позволяют проверить:

- доступность чат-виджета;
- базовую работоспособность элементов интерфейса;
- реальные пользовательские действия в браузере;
- интеграцию с `iframe` и browser behavior.

### Почему используются API-тесты
API-тесты позволяют быстрее и стабильнее проверить:

- бизнес-логику ассистента;
- структуру потокового ответа;
- сохранение контекста между сообщениями;
- уточняющие реакции на неполные запросы;
- наличие suggestions и специальных event token.

### Почему не везде используется точное сравнение текста
Ответы чат-ассистента могут быть вариативными, поэтому часть проверок выполняется по:

- ключевым словам;
- признакам уточнения;
- структуре stream-событий;
- наличию нужных token;
- наличию suggestions.

Такой подход лучше подходит для тестирования диалогового ассистента, чем жёсткое сравнение полного текста ответа.

---

## Ограничения и риски

При тестировании чат-ассистента важно учитывать следующие ограничения:

- UI-тесты зависят от стабильности внешнего сайта и DOM-структуры;
- ответы ассистента могут быть вариативными;
- часть проверок намеренно построена на ключевых признаках ответа, а не на полном точном совпадении текста;
- API-тесты зависят от доступности тестового окружения и корректно заданных переменных окружения.

## Подготовка окружения

### 1. Клонировать репозиторий
```bash
git clone <repository_url>
cd travel_assistant_simple_UI_tests
```

### 2. Создать виртуальное окружение
```bash
python -m venv .venv
```

### 3. Активировать виртуальное окружение
Для macOS / Linux:
```bash
source .venv/bin/activate
```

Для Windows:
```bash
.venv\Scripts\activate
```

### 4. Установить зависимости
```bash
pip install -r requirements.txt
```

### 5. Настроить переменные окружения
Создай файл `.env` и укажи необходимые значения переменных окружения.

> Если в проекте используется файл `.env.example`, можно создать `.env` на его основе.

---

## Переменные окружения

| Переменная | Назначение | Обязательность |
|------------|------------|----------------|
| `TEST_HOST` | базовый URL API | обязательно для API |
| `API_TOKEN` | токен авторизации API | опционально |
| `COOKIE` | cookie для API-авторизации | опционально |
| `LOGIN` | логин для remote Selenium / Selenoid | обязательно для remote UI |
| `PASSWORD` | пароль для remote Selenium / Selenoid | обязательно для remote UI |

### Важно

Файл `.env` не включён в проект намеренно, так как содержит чувствительные данные для доступа к рабочему стенду.
В составе проекта и сдаваемых материалов должен присутствовать только шаблон `.env.example` без реальных значений.

Для локального запуска необходимо самостоятельно создать файл `.env` на основе `.env.example` и заполнить его валидными данными доступа.

Пример создания локального `.env`:

```bash
cp .env.example .env
```

## Запуск в удалённой среде / Selenoid

Проект поддерживает удалённый запуск UI-тестов через Selenium Hub / Selenoid при наличии соответствующей внешней инфраструктуры.

Пример команды запуска:

```bash
pytest tests/ui \
  --base-url="https://www.tutu.ru/" \
  --remote-url="https://selenoid.qa.guru/wd/hub" \
  --browser="chrome" \
  --browser-version="148.0" \
  --headless="false" \
  --remote="true" \
  --window-size="1920x1080" \
  --alluredir=allure-results
```

При удалённом запуске в Allure могут прикладываться дополнительные артефакты, включая видео прохождения теста.
